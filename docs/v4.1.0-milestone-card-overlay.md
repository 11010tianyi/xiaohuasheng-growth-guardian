# v4.1.0 — 里程碑卡片科学详情弹窗 + 日记关联里程碑

## 版本概要

为所有里程碑/疫苗/体检/仪式卡片添加点击弹窗详情，展示科学解释（Markdown 渲染）+ 权威来源链接。日记编辑器新增里程碑关联下拉框，保存时自动编码为 `📌` 标签，查看日记详情时展示关联里程碑的科学解释。

新增全局函数，所有页面共享：

## 2. 日记里程碑关联

### 2.1 状态变量（`diary.js`）

- `_selectedMilestoneId`（string）— 当前编辑器中选中的里程碑 ID
- `_milestoneItems`（array）— `{id, name, category}` 扁平数组

### 2.2 编辑器 UI

**新增 `.diary-milestone-selector`**（标签选择器下方）：

```html
<div class="diary-milestone-selector">
  <label>关联里程碑（可选）</label>
  <select id="diary-milestone-select">
    <option value="">不关联</option>
    <!-- 按 category 分组动态生成 -->
  </select>
</div>
```

- 使用 `<optgroup>` 按 category 分类
- `populateMilestoneSelect()` 在 `setupEditorEvents()` 中调用
- `change` 事件更新 `_selectedMilestoneId`

### 2.3 数据流

```
保存 (handleSave)
  ├─ _selectedMilestoneId 非空
  ├─ findMilestoneItem() 查找里程碑
  ├─ 编码为 "📌 {title/name}" 标签
  └─ 存入 tags[] + entryData._milestoneId

加载 (loadEntries)
  └─ 遍历 tags，匹配 "📌 " 前缀
     └─ findMilestoneByName() 反查 ID → entry._milestoneId

编辑 (editEntry)
  └─ 恢复 _selectedMilestoneId → 设置 <select> 值

重置 (resetEditor)
  └─ 清空 _selectedMilestoneId → 重置 <select>
```

### 2.4 详情展示（showEntryDetail）

关联里程碑的日记在底部展示：

1. **分隔线** + **"关联里程碑: {title}"** 标题（加粗衬线字体）
2. **科学解释**（Markdown 渲染）：超过 300 字符时折叠，显示"展开全部"链接
3. **参考来源**：浅色圆角背景块，来源名称可点击跳转（`target="_blank"`）

## 5. 安全补丁：PIN 失败次数 + 15 分钟冷却

### 5.1 背景

v4.1.0 之前的认证方案仅对 `pin_hash` 做 SHA-256 哈希比对，无失败计数或冷却机制，存在暴力破解风险。

### 5.2 新增表（supabase-setup.sql 519-917 行）

#### `login_attempts`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | `UUID PRIMARY KEY DEFAULT gen_random_uuid()` | 主键 |
| phone | `TEXT UNIQUE NOT NULL` | 手机号 |
| failed_count | `INT NOT NULL DEFAULT 0` | 连续失败次数 |
| locked_until | `TIMESTAMPTZ` | 锁定截止时间（NULL 表示未锁定） |
| last_failed_at | `TIMESTAMPTZ` | 上次失败时间 |
| created_at | `TIMESTAMPTZ DEFAULT now()` | 创建时间 |
| updated_at | `TIMESTAMPTZ DEFAULT now()` | 更新时间 |

#### 行级安全

```sql
ALTER TABLE public.login_attempts ENABLE ROW LEVEL SECURITY;
CREATE POLICY login_attempts_isolated ON public.login_attempts
  FOR ALL TO anon USING (false);
```

所有读写只能通过 `verify_user_pin()` 进行。

### 5.3 新 RPC：`verify_user_pin(phone, pin_hash, increment_fail)`

单一入口校验 PIN 密码：

```sql
verify_user_pin(p_phone TEXT, p_pin_hash TEXT, p_increment_fail BOOLEAN)
RETURNS JSON
```

| 返回字段 | 类型 | 说明 |
|----------|------|------|
| `ok` | `boolean` | 校验是否通过 |
| `phone` | `text` | 用户手机号 |
| `phone_masked` | `text` | 脱敏手机号 |
| `remaining_attempts` | `int` | 剩余尝试次数（上限 5 次） |
| `locked_until` | `timestamptz` | 锁定过期时间 |
| `message` | `text` | 中文提示消息 |
| `is_new` | `boolean` | 是否新建用户 |

**锁定策略**：
- 5 次连续失败 → `locked_until = now() + interval '15 minutes'`
- 锁定期间所有操作（登录、打勾、日记 CRUD）拒绝
- 每次成功验证后清零 `failed_count`

### 5.4 受影响 RPC 全部覆盖

以下 7 个 RPC 均已通过 `CREATE OR REPLACE FUNCTION` 重写，内部调用 `verify_user_pin()`：

| RPC | 作用 |
|-----|------|
| `login_user` | 登录（失败计数+1；成功清零） |
| `toggle_milestone` | 打勾/取消打勾 |
| `create_diary_entry` | 创建日记 |
| `get_diary_entries` | 查询日记列表 |
| `update_diary_entry` | 更新日记 |
| `delete_diary_entry` | 删除日记 |
| `get_or_create_user` | 查询/创建用户（无增计数） |

所有 RPC 返回统一错误结构：

```json
{ "success": false, "message": "……", "remaining_attempts": N, "locked_until": "……" }
```

前端的 `supabaseLogin` / `handleAuthSubmit` 直接读取 `result.data.message` 展示错误提示，支持 `remaining_attempts` 自动拼接到提示文案。

### 5.5 运维命令

手动解锁：

```sql
UPDATE public.login_attempts
SET failed_count = 0, locked_until = NULL, last_failed_at = NULL, updated_at = now()
WHERE phone = '手机号';
```
