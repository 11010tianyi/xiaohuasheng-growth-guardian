# v5.0.0 — 语音打卡 + AI 日志增强

## 版本概要

新增语音打卡功能：一键录音 → 浏览器 Web Speech API 识别 → Supabase Edge Function（DeepSeek AI）语义分析 → 自动匹配里程碑 + 日志内容增强（摘要、创作、亲子提问、标签）。同时支持纯日志记录（无打卡匹配）和有打卡匹配时的独立操作（打卡与存日志可分别执行）。

## 2. 语音识别引擎

### 2.1 浏览器兼容性

| 浏览器 | 状态 | 原因 |
|--------|------|------|
| Safari (macOS/iOS) | ✅ 可用 | WebKit Speech Recognition 正常工作，`file://` 下 `onend` 不触发（已绕过） |
| Chrome/Edge (桌面) | ❌ 被墙 | 调用 Google/Azure 云端 STT 服务器在国内被封锁：Chrome 只返回 interim 结果永不触发 onend；Edge 开始即 network 错误 |
| Android Edge/Chrome | 🤷 未验证 | 待用户在局域网 `http://<PC-IP>:8080` 测试 |

### 2.2 配置参数

```js
recognizer.lang = 'zh-CN';
recognizer.continuous = true;      // 持续监听，不自动停止
recognizer.interimResults = true;  // 获取中间结果作为 fallback
```

### 2.3 关键绕过方案

#### `onend` 永不触发（`file://` 协议）

Safari 下 `file://` 打开的页面，`SpeechRecognition.onend` 事件永远不会触发。解决方案：

```js
function stopListening() {
  // ... 停止 recognizer ...
  // 不依赖 onend，直接用 setTimeout 处理最终结果
  setTimeout(function() {
    handleVoiceTranscript(finalTranscript || interimTranscript);
  }, 400);
}
```

`setTimeout(400ms)` 给浏览器一点时间把最后的 `onresult` 事件派发完毕。

#### 中间结果 fallback

在国内网络环境下 Chrome 可能只返回 `isFinal=false` 的中间结果，永不返回 `isFinal=true`。此时 `finalTranscript` 始终为空字符串，回退到 `interimTranscript`：

```js
handleVoiceTranscript(finalTranscript || interimTranscript);
```

### 2.4 静默自动终止

```
onresult 触发 → 有语音内容 → 重置 5 秒计时器
                      → 无语音内容 → 不重置
5 秒倒计时归零 → 自动调用 stopListening() → 显示"已自动停止（5秒无语音）"
```

## 3. Edge Function：`parse-milestones`

### 3.1 部署

```bash
# 设置 DeepSeek API Key 为 Supabase Secret
npx supabase secrets set DEEPSEEK_API_KEY=<your-key> --project-ref rhfbhnbstpufgnasrzrm

# 部署 Edge Function（不校验 JWT，因为前端用 anonKey 调用）
npx supabase functions deploy parse-milestones \
  --no-verify-jwt \
  --project-ref rhfbhnbstpufgnasrzrm \
  --token <your-supabase-access-token>
```

部署成功后通过以下 URL 调用：

```
https://rhfbhnbstpufgnasrzrm.supabase.co/functions/v1/parse-milestones
```

### 3.2 技术细节

- **运行时**: Deno（Supabase Edge Functions 默认运行时）
- **CORS**: 通配 `*`，处理 OPTIONS 预检请求（204 空响应），允许所有来源调用
- **认证**: `--no-verify-jwt` 模式，前端用 Supabase anonKey + `Authorization: Bearer` 请求
- **模型**: DeepSeek Chat（`deepseek-chat`），温度 `temperature=0.1` 保证匹配稳定性
- **输出格式**: 强制 `response_format: { type: 'json_object' }`，确保返回可解析的 JSON

### 3.3 请求/响应格式

**请求**：
```json
{
  "transcript": "今天带宝宝打了乙肝疫苗第二针",
  "milestones": [
    { "id": "s01-001", "title": "出生证明办理" },
    { "id": "s01-002", "title": "乙肝疫苗第2剂" },
    ...所有 331+ 条里程碑
  ]
}
```

**响应**：
```json
{
  "matched": [
    { "id": "s01-002", "title": "乙肝疫苗第2剂" }
  ],
  "summary": "家长说今天带孩子接种了乙肝疫苗第二针",
  "diary": {
    "summary": "宝宝今天完成了乙肝疫苗第二针的接种，这是国家免疫规划的重要节点。",
    "creative_response": "",
    "aristotle_question": "疫苗是怎么帮助我们的身体抵抗疾病的呢？",
    "tags": ["疫苗", "健康检查", "打卡"]
  }
}
```

### 3.4 Prompt 设计要点

```
系统提示词结构：
1. 角色定义：儿童成长记录助手
2. 匹配规则：灵活匹配——同义词、口语化、部分匹配（"满月"→月龄1个月、"打针"→疫苗）
3. 无论是否匹配到里程碑，都做日记分析：
   - 创作需求检测（写诗/故事/描述场景）
   - 亚里士多德式提问（亲子交流引导）
   - 内容摘要（2-3句话）
   - 建议标签（1-3个）
4. 严格 JSON 输出，禁止额外文字
```

**关键要素**：
- `temperature: 0.1`：低温度确保里程碑匹配的一致性
- 所有里程碑标题传入作为上下文（331+ 条），AI 自主匹配
- `creative_response`：当用户表达创作需求时（"写一首关于春天的小诗"），AI 完成创作；否则返回空字符串
- 无论是否匹配里程碑，`diary` 对象始终返回

## 4. 前端语音模块

### 4.1 FAB 按钮

所有页面自动注入右下角悬浮按钮（`initVoiceCheckin()` 在 `initGrowthGuardian()` 中调用）：

```css

  position: fixed;

  right: 20px;
  z-index: 3000;
  width: 56px;
  height: 56px;
  border-radius: 50%;
  background: linear-gradient(135deg, #7CB87C, #5A9A5A);

```

状态变化：
- **空闲**: 🎤 绿色渐变
- **录音中**: ⏹ 红色渐变 + 呼吸动画脉冲
- **点击停止**: 处理识别结果

### 4.2 聆听状态指示器

固定位置底部居中（`bottom: 170px`），绿色背景白字：

```css
.gg-voice-status {
  position: fixed;
  bottom: 170px;
  left: 50%;
  transform: translateX(-50%);
  background: #2d5016;
  color: #fff;
  padding: 10px 24px;
  border-radius: 30px;
  z-index: 3999;
  opacity: 0;
  transition: opacity .3s;
  pointer-events: none;
  white-space: nowrap;
}
.gg-voice-status.show { opacity: 1; }
```

- `pointer-events: none`：不干扰点击事件
- `white-space: nowrap`：防止换行
- 仅在录音中显示（`showVoiceStatus()` / `hideVoiceStatus()`）

### 4.3 确认弹窗

`buildVoiceOverlay(innerHtml)` 生成半透明模糊背景 + 白色圆角面板。

**无里程碑匹配**：
- 显示 AI 摘要、创作、亚里士多德提问、标签
- 一个"保存到日记"按钮 → 保存后立即关闭

**有里程碑匹配**：
- 显示匹配列表（绿色 badge 显示 ID）
- 两个操作按钮：
  - **确认打卡 N 项**：调用 `batchToggleMilestones()` 批量打卡，按钮变灰 `✅ 已打卡`，弹窗不关闭
  - **📝 保存到日记**：生成 Markdown 日记（含打卡关联 `📌` 标签），调用 `create_diary_entry` RPC 保存，按钮变灰 `✅ 已保存`，弹窗不关闭
- 两个按钮点完最后一个才关闭弹窗，支持任意顺序

### 4.4 标签系统

```js
function buildTags(baseTags, matchedItems) {
  // 1. 始终包含 "语音记录"
  // 2. 对每个匹配里程碑，添加 "📌 里程碑名称"
  return tags;
}
```

- 无论是否匹配里程碑，`语音记录` 标签始终存在
- 匹配里程碑时，每个里程碑转换为 `📌 {title}` 标签，和手动写日记时选择里程碑关联的效果完全一致
- AI 建议的标签保留

## 5. CORS 配置

Edge Function 必须正确处理跨域请求。非简单请求（POST + JSON Content-Type）会触发浏览器预检：

**OPTIONS 处理**（return 204，不继续执行主逻辑）：
```typescript
if (req.method === 'OPTIONS') {
  return new Response(null, { status: 204, headers: corsHeaders() })
}
```

**响应头**：
```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: POST, OPTIONS
Access-Control-Allow-Headers: authorization, x-client-info, apikey, content-type
```

所有响应（成功/错误）都附带 CORS 头。

## 8. 已知问题与限制

### 8.1 Chrome/Edge STT 被墙

国内网络环境下 Chrome（Google STT）和 Edge（Azure STT）的云端语音识别服务器无法访问：
- Chrome: 只返回 `isFinal=false` 的中间结果，`onend` 永不触发，最终 `finalTranscript` 为空
- Edge: 开始录音立即 `network` 错误

**临时方案**：使用 Safari（macOS/iOS），WebKit Speech Recognition 正常工作。

**长期方案**：待用户在 Android Edge 上通过局域网 `http://<PC-IP>:8080` 测试。

### 8.2 `file://` 协议下 `onend` 不触发

Safari 从本地文件系统打开页面时，`SpeechRecognition.onend` 事件不触发。已通过 `setTimeout(400ms)` 绕过。

### 8.3 中间结果替代终稿

由于 Chrome 可能不返回最终结果，`stopListening()` 回退到 `interimTranscript`。中间结果通常准确度略低于终稿，但可用。

### 8.4 无 Supabase 配置时

未配置 `supabase-config.js` 时，应用其他功能不受影响，仅语音打卡不可用。
